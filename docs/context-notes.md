## 착수발표의 초기 계획

- ECG·PPG 생체데이터와 차량 CAN 데이터를 융합해 운전자 상태를 판단.
- 초기 분류 목표: 매우 양호 / 양호 / 피로 / 상태 이상.
- 생체 특징 후보: R-peak, R-R 간격, HRV. 각 특징의 ECG·PPG 적용 방식은 후속 설계 필요.
- CAN 후보: 속도, RPM, 조향각, 페달, 제동, 차선 관련 정보.
- 운전자별 평상시 생체신호·운전패턴을 학습하고 현재 상태와의 변화량을 반영.
- 보드에서 수집부터 판단까지 수행하고, 실시간 입력이 어렵다면 파일 Replay 지원.
- HMI, 휴식 권고, 부저·LED, 공조·조명·오디오 연계는 서비스 후보.

## 후속 질의 내용

### 데이터

- ECG·PPG 등의 데이터셋은 자체 제공 예정이며, PPG 보정 로직도 있다고 기록됨. 실제 수령 여부와 제공 범위는 미확인.
- CAN은 AI를 활용해 dummy 데이터를 제작할 수 있음. 세부 가이드라인은 Replay 데이터를 확인한 뒤, 가능할 경우 제공 예정.
- 추가 데이터와 공개 데이터셋 사용 가능.
- 핵심은 AI 모델로 운전자 상태를 판단하는 것.
- 생체데이터 : 차량데이터 8:2 비율 권장. 비율을 적용하는 구체적 단위는 미정.
- 차량데이터는 부가 정보로 활용하는 방향.
- 라벨 기준은 정해지지 않았으며 정수형보다는 구간화 선호.
- 제안서의 양호 / 이상 같은 상태 명칭도 임시 용어.

### AI 모델

AI 관련 질문에는 답변이 어렵다고 기록되어 있습니다. 모델 구조나 학습 방식을 기업이 확정한 것으로 해석하지 않으며, 팀의 비교 실험이 필요합니다.

### 개인화 Baseline

- 가능하다면 사용자 n명의 정보를 저장하고, 각 사용자의 생체정보와 운전습관 정보를 유지하는 방향.
- 질의 메모에는 현재 임계값으로 이상을 판단하고 이를 운전자별 Baseline 기반 판단으로 바꾸는 방향이 제시됨.
- 이 기록만으로 현재 저장소에 임계값 기반 구현이 존재한다고 판단할 수는 없음.

### HMI

HMI 구현이 결과물의 품질에 도움이 될 것으로 예상된다는 권장 의견입니다. 필수 범위와 연계 대상은 추가 협의가 필요합니다.

## 자료 간 차이와 문서 반영 기준

| 항목 | 착수발표 | 후속 질의 | 현재 문서 처리 |

| 분류 | 4단계 목표 | 명칭·라벨 기준 미정 | 4단계는 초기 목표로 유지, 최종 클래스는 미확정 |
