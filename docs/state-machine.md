# 추론 후단: 윈도우 판정과 졸음 상태 머신 (v0.3)

> 2026-11-05 확정: 분류기는 **2클래스(정상/졸음)**, 최종 표시는 **3단계(정상 → 주의 → 졸음)**. 데이터팀 심박 클래스(심박 변화, 큰 심박 하락)는 일단 쓰지 않습니다. 시간 기준은 시연에서 변화가 바로 보이도록 **10초**입니다.
>
> 코드: `src/driver_state/state_machine.py`, 설정: `configs/default.yaml`의 `input.state_machine`.

## 1. 전체 흐름

```text
10초마다 새 윈도우 (최근 30초)
 → ① 윈도우 판정  ── 불통과 ──▶ -1 (판정 불가) ──┐
 │      통과                                       │ 전이 계산에서 제외
 → ② 분류기 P(졸음) = p_t                          │ (직전 단계 유지)
 → ③ 누적 점수 s_t                                  │
 → ④ 단계 전이 (정상 / 주의 / 졸음) ◀──────────────┘
         -1 이 60초 연속이면 '측정 불가' 표시 후 초기화
```

윈도우 30초, 이동 10초이므로 판정은 10초마다 한 번 나옵니다. 판정 시각 t는 윈도우의 **끝** 시각입니다.

## 2. 윈도우 판정 (-1 처리)

아래 중 하나라도 해당하면 그 윈도우는 -1(판정 불가)이며, 분류기 출력은 쓰지 않습니다.

| 조건 | 기본값 | 의미 |
| --- | --- | --- |
| 품질 불량 | 평탄(표준편차 < 1e-6), 포화(최솟값·최댓값 샘플 > 5%), 값이 1초 넘게 멈춤 | 접촉 불량, 센서 포화, 전송 끊김 |
| 특징 계산 불가 | 생체 특징 8개 중 NaN 하나 이상 | 박동 간격이 3개 미만인 채널이 있음 |
| 유효 RR 부족 | 30초 윈도우 안 유효 RR < 20개 (`gate_min_ibi`) | R-peak 검출 실패. 심박 40 bpm 이하면 걸릴 수 있어 조정 대상 |
| ECG·PPG 불일치 | \|HR − PR\| > 10 bpm (`gate_max_hr_ppg_diff`) | 두 센서 중 하나가 잘못 측정 |

- HR: ECG 평균 심박수, PR: PPG 평균 맥박수 [bpm].
- "값이 멈춤" 검사는 이번에 추가했습니다. 윈도우 일부만 끊긴 경우, 업샘플 보간의 overshoot 때문에 포화 검사로는 잡히지 않았습니다.

## 3. 누적 점수

$$s_t = \alpha\, p_t + (1-\alpha)\, s_{t-1}, \qquad s_{\text{첫 유효 윈도우}} = p_t$$

- $p_t$: 판정 시각 $t$ 윈도우의 분류기 출력 P(졸음) (0~1).
- $s_t$: 누적 점수(지수이동평균, EMA). 한 윈도우의 튀는 값을 완화합니다.
- $\alpha$: 새 값 반영 비율 (기본 0.5). 클수록 빠르게 반응하고, 작을수록 안정적입니다.

## 4. 단계 전이

| 기호 | 기본값 | 의미 |
| --- | --- | --- |
| $\theta_{on}$ | 0.6 | $s_t > \theta_{on}$ 이면 "졸음 쪽" 시간을 누적 |
| $\theta_{off}$ | 0.4 | $s_t < \theta_{off}$ 이면 "회복 쪽" 시간을 누적 |
| $T_{up}$ | 10 s | 졸음 쪽 누적이 $T_{up}$ 이 되면 한 단계 상승 (정상→주의→졸음), 누적 0으로 |
| $T_{down}$ | 10 s | 회복 쪽 누적이 $T_{down}$ 이 되면 한 단계 하강 (졸음→주의→정상), 누적 0으로 |
| $T_{hold}$ | 60 s | -1 판정이 연속 $T_{hold}$ 이면 '측정 불가' |

- $\theta_{off} \le s_t \le \theta_{on}$ (히스테리시스 구간): 단계와 누적을 그대로 둡니다. 경계 근처에서 단계가 깜빡이는 것을 막습니다.
- 반대쪽 조건이 나오면 이쪽 누적은 0이 됩니다. 즉 "연속으로" 쌓여야 전이합니다.
- 10초 기준이면 판정 1회마다 한 단계씩 움직입니다. 정상에서 졸음까지 최소 20초, 회복도 최소 20초입니다.

**예시** ($\alpha=0.5$, 10초마다 판정):

| t (s) | 10 | 20 | 30 | 40 | 50 | 60 | 70 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| $p_t$ | 0.1 | 0.9 | 0.9 | 0.9 | 0.5 | 0.1 | 0.1 |
| $s_t$ | 0.10 | 0.50 | 0.70 | 0.80 | 0.65 | 0.38 | 0.24 |
| 단계 | 정상 | 정상 (구간 안) | 주의 | 졸음 | 졸음 | 주의 | 정상 |

## 5. -1 이 이어질 때

- **짧은 -1**: 그 윈도우를 건너뜁니다. 단계·점수·누적을 그대로 유지합니다.
- **연속 -1 ≥ 60초**: '측정 불가'(level −1)를 표시하고, 점수·누적·단계를 초기화합니다. 다음 유효 윈도우부터 정상에서 다시 시작합니다.
- 60초로 둔 이유: 윈도우가 30초이고 10초씩 겹치므로, 1초짜리 끊김도 윈도우 3~4개(판정 30~40초)를 -1로 만듭니다. 60초면 실제 신호가 약 30초 끊겼을 때만 '측정 불가'가 됩니다.

## 6. 출력 (`StatePredictor` → `WindowResult`)

| 필드 | 내용 |
| --- | --- |
| `t_start`, `t_end` | 윈도우 시작·끝 [s] (끝 = 판정 시각) |
| `state`, `state_name`, `proba` | 분류기 결과 0 정상 / 1 졸음. 판정 불가면 -1, `proba` 빈 리스트 |
| `valid`, `invalid_reason` | 윈도우 판정 통과 여부와 사유 |
| `level`, `level_name`, `score` | 최종 단계 0 정상 / 1 주의 / 2 졸음 / -1 측정 불가, 누적 점수 $s_t$ |
| `quality_ok`, `baseline_valid` | 품질 검사 결과, 개인 기준 사용 여부 |

`predict_windows`를 시간 순서대로 반복 호출하면 상태가 이어집니다(실시간). `predict_recording`과 `set_profile`은 상태 머신을 처음부터 다시 시작합니다.

## 7. 평가 (`timeline_metrics`)

분류기는 윈도우 단위 Macro-F1(LOSO)로, 상태 머신은 녹화 타임라인으로 평가합니다.

| 지표 | 정의 |
| --- | --- |
| 감지 지연 | 정답이 졸음으로 바뀐 판정 시각부터 처음 '졸음' 단계가 될 때까지 [s] |
| 놓침 | 졸음 구간이 끝날 때까지 '졸음' 단계가 안 나온 횟수 |
| 오경보 | 정답이 정상인 시각에 '주의' 이상으로 올라간 횟수 |
| 측정 불가 비율 | 판정 중 level −1 비율 |

정답은 판정 시각(윈도우 끝)의 라벨입니다. 윈도우가 과거 30초를 보므로 지연에는 윈도우 길이에 의한 지연이 포함됩니다. 임계값($\alpha, \theta, T$)을 데이터로 맞출 때는 LOSO 검증 참가자로만 맞춥니다.

`python scripts/demo_pipeline.py`로 합성 시연(정상 60초 → 졸음 120초 → 정상 120초, 중간 8초 PPG 끊김)을 돌리면 판정 표와 위 지표가 출력됩니다. 합성 데이터 결과: 감지 지연 30초, 놓침 0, 오경보 0. 끊긴 구간 판정 3회는 -1로 처리되고 '졸음' 단계가 유지됩니다.
