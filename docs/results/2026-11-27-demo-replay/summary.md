# 11-18 실측 시연 클립과 재생 구간 (2026-11-27)

입력: `측정 26.11.18 19 42.zip`의 원본 ECG·PPG (ECG 435.33 Hz, PPG 100.66 Hz, 2100초).
근거: 전체 기록을 웹보드 판정 재생(LocalReplay, Pi와 같은 경로, S1-EP, `--rpeak-threshold rolling`)으로 끝까지 돌린 결과
(`scripts/replay_timeline.py`). 기준은 같은 기록 앞부분(유효 창 20개, 재생 위치 521초에 완료).

## 판정 단계 시각표 (원본 시각)

| 원본 시각 | 단계 |
|---|---|
| 310초 | 정상 (첫 판정) |
| 590초 | 주의 |
| 790초 | 주의 + 졸음 후보 |
| **1010초** | **졸음** (지속 조건으로 확정, CAN 없음) |
| 1500초 | 주의 |
| 1560초 | 정상 |
| 1660초 | 주의 → 1740초 후보 → 2040초 졸음 |

라벨 표시(원본 시각): 0~600초 정상, 600~1500초 졸음, 1500~2100초 정상 (블록 끝에 찍힌 자기보고).

## 시연 클립 (`python scripts/make_demo_replays.py <zip> --out outputs/local-recordings/demo_1118 --preset rec20261118`)

| 클립 | 원본 구간 | 빠르게 넘김 | 화면 구간 (원본 시각) | 화면 판정 | Unity 기록 시각 |
|---|---|---|---|---|---|
| `1118_baseline` | 0~540초 | 없음 | 기준 계산용 | - | - |
| `1118_normal` | 0~580초 | 앞 320초 | **320~580초** | 정상 | **260~520초** |
| `1118_drowsy` | 0~1345초 | 앞 1285초 | **1285~1345초** (1분, 졸음 확률 최고) | 졸음 | **1225~1285초** |
| `1118_full` | 0~2100초 | 없음 | 전체 | 위 표 | 0~2040초 |

- 정상·졸음 클립은 원본 0초부터 시작하므로 판정이 전체 재생과 같다 (모델 300초 장기 특징 창과 상태 머신 지속 조건을 실제 측정값으로 채움).
- Unity 기록 시각 = 원본 시각 − 60초. Unity Replay(`convert_recording.py`)는 약 60.0초부터 시작하는 라벨링 파일로 만들어진다.
  Unity에서 같은 장면을 재생하려면 시작 오프셋을 위 Unity 기록 시각의 시작값(정상 260초, 졸음 1225초)으로 주고, 서버 프리롤은 300초 이상을 준다.
  Unity 서버는 자체 기준·프리롤을 쓰므로 단계 전환 시각은 몇십 초 다를 수 있다 (화면 확인 필요).

## 웹보드 실행

```
python scripts/run_dashboard.py --recordings-dir outputs/local-recordings/demo_1118 --rpeak-threshold rolling
```
1. 사용자 설정 → `1118_baseline`으로 기준 계산·저장.
2. 판정 기록으로 `1118_normal` 또는 `1118_drowsy`를 고르고 1배속 재생. 앞부분은 기다리지 않고 처리되고("시연 앞부분 빠르게 처리 중"), 끝나면 화면 구간부터 1배속으로 이어진다. 위치 표시에 원본 시각이 같이 나온다.
3. `global` 임계(기본)로는 이 기록의 기준 계산이 실패한다 (420~480초 잡음, PR #17).

## 확인하지 못한 것

- Pi에서 앞부분 빠르게 넘기기 소요 시간 (개발 PC에서는 전체 2100초 판정이 약 4~5분).
- 화면에서 클립을 직접 재생한 확인. 클립의 판정은 전체 재생 결과에서 가져왔다.
- 원본 클립은 개인 생체 데이터라 저장소에 올리지 않는다 (`outputs/`).

## 졸음 전환 30초 (`1118_to_drowsy`, 현장 시연용)

화면 원본 990~1020초 (Unity 930~960초). 앞 990초는 빠르게 처리.

| 원본 | Unity | 단계 | 점수 |
|---|---|---|---|
| 990 | 930 | 주의 (졸음 후보) | 0.66 |
| 1000 | 940 | 주의 (졸음 후보) | 0.65 |
| **1010** | **950** | **졸음** (지속 조건 확정) | 0.59 |
| 1020 | 960 | 졸음 | 0.59 |

CAN 없이 상태 머신 v2는 정상 → 주의(40초) → 졸음 후보(60초) → 졸음(추가 180초)을 거치므로 30초 안에 정상 → 졸음으로 바로 바뀌는 구간은 없다.
이 기록의 정상 → 주의 전환은 590초 (Unity 530초).
