# 데이터·모델 설계 메모

아래는 착수발표와 후속 질의에서 확인한 방향 및 설계 검토 항목입니다. 구현 기술과 실험 조건은 아직 확정하지 않았습니다.

## 입력 데이터

| 입력 | 역할 | 현재 정보 | 추가 확인 |
| --- | --- | --- | --- |
| ECG | 주요 생체 입력 | 데이터 제공 예정; R-peak, R-R, HRV 특징 검토 | 형식, 주기, 품질, 상태 라벨 |
| PPG | 주요 생체 입력 | 데이터 및 보정 로직 제공 예정 | 보정 방식, 모션 아티팩트, 특징 정의 |
| CAN | 운전 상황의 보조 정보 | Replay 검토 후 가이드라인 제공 가능; dummy 제작 가능 | 신호 목록, 주기, 생체 데이터와의 대응 관계 |
| 공개·추가 데이터 | 데이터 보완 | 활용 가능하다는 질의 내용 | 사용 조건, 라벨 일치, 도메인 차이 |

생체 : 차량 8:2는 권장 방향입니다. 이를 특징 개수나 융합 가중치로 바로 고정하지 않고 적용 의미를 먼저 확인합니다.

## 전처리 및 특징 추출

1. 타임스탬프와 샘플링 주기를 확인하고 생체·CAN을 동일 시간축에 정렬.
2. 생체신호의 노이즈와 모션 아티팩트를 줄이고 제공 PPG 보정 로직의 적용 여부 확인.
3. Window Size와 Overlap을 정해 특징 추출. 기업 가이드라인이 없다면 팀 실험으로 선정.
4. 생체 특징과 보조 차량 특징을 결합해 상태 판단 모델 입력 구성.

Window Size, Overlap, 결측치 처리, 정규화와 시간 허용 오차는 미정입니다.

## 라벨 및 검증

초기 계획은 4단계 분류이나, 후속 질의에서는 상태 용어와 라벨 기준이 미정이라고 정리되었습니다. 구간화가 무엇을 기준으로 이루어지는지도 확인해야 합니다.

착수발표에서는 HRV로 생성한 라벨을 HRV 입력으로 그대로 맞추는 순환 논리를 우려했습니다. 기업 제공 라벨과 공개 데이터의 정의를 우선 확인하고, 라벨 생성 지표와 입력 특징의 관계를 검토합니다.

다음은 문서 정리 과정에서 추가한 **검증 제안**이며 확정 요구사항은 아닙니다.

- 운전자 단위로 학습·검증·테스트를 분리하고, 겹치는 시간 Window가 분할 사이에 섞이지 않도록 설계.
- 생체 단독과 생체+CAN 모델을 비교하여 보조 차량 정보의 효과 확인.
- 고정 기준과 개인별 Baseline을 비교하여 개인화 효과 확인.
- dummy CAN 결과와 실제·Replay CAN 결과를 구분해 보고.
- 클래스별 성능, 혼동행렬, 추론 지연과 보드 자원 사용량을 함께 확인. 목표 수치는 별도 합의.

## 개인별 Baseline

운전자별 생체정보와 운전습관 프로필을 로컬에서 유지하고, 평상시 대비 변화량을 판단에 반영하는 방향입니다.

| 검토 항목 | 선택지 또는 쟁점 |
| --- | --- |
| 생성 시점 | 주행 초기 N분으로 고정 / Rolling Window로 갱신 |
| 초기 상태 오염 | 출발부터 이상 상태인 경우를 정상 기준으로 학습할 위험 |
| 보완 방식 | 절대 임계값 병행 / 누적 정상 프로필 활용 검토 |
| 모델 결합 | 별도 구조 / fine-tuning 등 비교 |
| 저장 방식 | 보드 로컬 스토리지, 로컬 DB 등 검토 |
| 사용자 관리 | 사용자 n명 구분 및 프로필 선택 방법 미정 |

Baseline의 생성 조건, 갱신·초기화 정책과 필요한 정상 데이터 길이는 미확정입니다.

## 배포와 서비스

- 진행 순서: PC 환경 검증 → 기업 중간 검토 → 타깃 SBC 확정 → 이식·경량화.
- 플랫폼 후보: Linux 기반 SBC 또는 동급 임베디드 플랫폼. 구체 보드 및 CPU/GPU 여부 미정.
- 런타임 후보: ONNX Runtime / TensorFlow Lite. 양자화 등 경량화 기법 검토.
- 실시간 입력이 어렵다면 동일 프로그램에서 파일 Replay 모드 지원.
- HMI 상태 표시와 알림을 검토하고, 부저·LED·휴식 권고 및 공조·조명·오디오 연계는 범위 협의 후 선정.

## 데이터 보관 원칙 제안

생체정보와 개인 프로필의 로컬 처리는 프로젝트 방향입니다. 아래 저장소 운영 원칙은 이를 위한 제안입니다.

- 원본 생체데이터와 사용자 프로필은 Git에 커밋하지 않음.
- 데이터 경로, 형식과 취득 방법만 문서화하고 예시는 합성 또는 비식별 데이터 사용.
- 실제 키·식별 정보가 포함된 환경 설정은 제외.
- 기업 자료와 공개 데이터셋은 이용 조건과 재배포 가능 여부 확인 후 사용.
