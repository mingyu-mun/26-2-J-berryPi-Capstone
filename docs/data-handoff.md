# 데이터 팀 인계: 모델 입력 데이터 전달 규약 (v0.3)

> 작성: AI 모델링 파트 · 2026-11-05 · 기준 문서: [공통 입력 규약](input-spec.md)
>
> 이 문서는 데이터/전처리 담당이 **무엇을, 어떤 형식으로** 넘겨주면 모델 학습과 시연 추론이 바로 돌아가는지 정리한 것입니다. 필터링·리샘플·윈도우 분할·특징 계산은 모델 쪽 공통 전처리가 처리하므로, 데이터 팀은 **raw 신호를 정확한 메타정보와 함께** 넘겨주면 됩니다.

## 1. 한눈에 보기

| 항목 | 요청 사항 |
| --- | --- |
| 채널 | `ecg`, `ppg` 2개 (CAN은 11/5 결정으로 모델 입력에서 제외, 후순위) |
| 값 | 센서 raw 값 그대로 (ADC 0~1023, mV 등 단위 무관) |
| 샘플링 | 채널별로 일정한 주기. ECG ≥ 250 Hz 권장, PPG ≥ 50 Hz |
| 시간 정렬 | 한 세션의 ECG·PPG는 같은 시각에 시작 (`t0` 공통) |
| 결측 | NaN·끊긴 구간 없이 연속 (있으면 4장 규칙대로 처리 후 전달) |
| 필터 | 적용하지 않은 raw 권장. 이미 필터를 적용했다면 `prefiltered: true` 표시 |
| 참가자 id | 참가자마다 고정 id (`S01`, `User1` 등). 모르면 `null` |
| 기준 구간 | 참가자별 첫 세션의 **앞 30초는 안정 상태(비주행, 앉은 자세)**로 측정 |
| 라벨 | 샘플 단위 정수 `0` 정상 / `1` 졸음 / `-1` 미라벨 (11/5 확정, 2클래스) |

## 2. 세션 1개 = 폴더 1개

```text
data/
└── <dataset_id>/                 # 예: jberry_sensor, cl_drive
    └── <subject_id>/             # 예: User1 (참가자 id 없으면 anon)
        └── <session_id>/         # 예: 2026-11-20_s1
            ├── meta.json
            ├── ecg.csv           # 한 열: value (헤더 1줄)
            ├── ppg.csv           # 한 열: value
            └── labels.csv        # 선택. 한 열: label (0 정상, 1 졸음, -1 미라벨)
```

`meta.json` 예시:

```json
{
  "dataset_id": "jberry_sensor",
  "subject_id": "User1",
  "session_id": "2026-11-20_s1",
  "t0": "2026-11-20T14:03:12+09:00",
  "fs": {"ecg": 250, "ppg": 50},
  "label_fs": 1,
  "is_rest": false,
  "prefiltered": false,
  "sensor": {"ecg": "AD8232", "ppg": "XD-58C"},
  "notes": "앞 30초 앉은 상태 기준 측정 후 시나리오 시작"
}
```

| 필드 | 필수 | 설명 |
| --- | --- | --- |
| `dataset_id` | O | 데이터 출처. 공개 데이터셋은 데이터셋 이름 |
| `subject_id` | O | 참가자 id 또는 `null`. `null`이면 개인 Baseline을 만들지 않음 |
| `session_id` | O | 세션 이름 |
| `t0` | O | 세션 시작 시각 (ISO 8601). 같은 참가자에서 가장 이른 세션이 기준 세션 |
| `fs` | O | 채널별 샘플링 주기 [Hz]. **실제 측정 주기**를 적을 것 (설정값과 다르면 실측값) |
| `label_fs` | 라벨 있을 때 | `labels.csv`의 샘플링 주기 [Hz] |
| `is_rest` | O | 휴식(기준) 측정 전용 세션이면 `true`. 이 세션은 Baseline 계산에만 쓰고 학습 윈도우로는 안 씀 |
| `prefiltered` | O | 노치·대역통과 필터를 이미 적용했으면 `true` |
| `sensor`, `notes` | 선택 | 센서 모델, 특이사항 |

CSV 대신 `.npz`(배열 `ecg`, `ppg`, `labels`)도 받을 수 있습니다. 모델 쪽 로더 `driver_state.data_io.load_tree("data/")`가 이 폴더 구조를 읽어 `Recording`으로 변환합니다. NaN이 있으면 오류를 내고 멈춥니다.

## 3. 기준 구간(Baseline) 측정 규칙

개인화 특징은 참가자마다 "평소 상태" 30초를 기준으로 계산합니다.

- **자체 수집:** 각 참가자의 첫 세션은 시작 후 **30초 이상 비주행·앉은 상태**로 측정합니다. 별도 휴식 세션을 따로 녹화했다면 `is_rest: true`로 표시합니다.
- **시연:** 시연 직전 시연자마다 비주행 상태로 30초 측정하고, 그 시연에서만 씁니다.
- **품질 기준 (미달 시 재측정):**
  - 30초 동안 유효 박동 간격(RR) 20개 이상
  - ECG 심박수와 PPG 맥박수 차이 10 bpm 이하
  - 신호가 평탄하지 않고(접촉 불량 아님), 최솟값·최댓값에 붙은 샘플이 5% 이하(포화 아님)
- 기준 구간과 겹치는 윈도우는 모델 쪽에서 학습·평가 대상에서 자동으로 뺍니다.

## 4. 데이터 팀에서 처리해 주셔야 할 것

| 문제 | 처리 방법 | 이유 |
| --- | --- | --- |
| 샘플 누락 (시리얼 전송 중 빠짐) | 타임스탬프 기준으로 균일 간격에 맞춰 재정렬하거나, 누락 구간 앞뒤로 세션 분리 | 모델 쪽 리샘플은 샘플 간격이 일정하다고 가정 |
| 짧은 결측·NaN (≤ 0.2초) | 선형 보간 | 필터가 NaN이 있으면 동작하지 않음 |
| 긴 결측 (> 0.2초) | 그 지점에서 세션 분리 (`session_id` 다르게) | 보간하면 가짜 박동이 생김 |
| ECG·PPG 시작 시각 차이 | 늦게 시작한 채널에 맞춰 앞부분 잘라내기 | 같은 윈도우가 같은 시간을 봐야 함 |
| 극성 반전 (ECG가 뒤집힘) | 그대로 전달 가능 | 모델 쪽 R-peak 검출은 제곱 에너지를 써서 극성에 무관 |

## 5. 모델 쪽 공통 전처리가 하는 것 (데이터 팀이 하지 않아도 됨)

1. 60 Hz 노치 필터 (전원 잡음)
2. 다운샘플 전 저역통과 필터 (anti-aliasing, 40 Hz)
3. 100 Hz 리샘플
4. 대역통과: ECG 0.5–40 Hz, PPG 0.5–8 Hz
5. 윈도우 품질 검사 (평탄·포화 윈도우 제외)
6. 30초 윈도우, 10초 이동 분할, HRV·PPG 특징 계산, 정규화

모션 아티팩트 제거와 기업 제공 PPG 보정 로직은 **아직 어느 쪽에도 들어 있지 않습니다**. 데이터 팀에서 적용한다면 `prefiltered: true`로 표시하고, 어떤 처리를 했는지 `notes`에 적어 주세요.

## 6. 공개 데이터셋을 넘길 때

공개 데이터셋도 2장과 같은 폴더 구조로 변환하면 됩니다. 아래 표로 Baseline을 어떻게 만들지가 정해집니다.

| 데이터셋 조건 | 할 일 | Baseline |
| --- | --- | --- |
| 참가자 id + 휴식 녹화 있음 | 휴식 녹화를 `is_rest: true` 세션으로 | 휴식 녹화 앞 30초 |
| 참가자 id + 연속 녹화만 | `t0`(또는 세션 순서)를 정확히 | 가장 이른 세션 앞 30초 |
| 참가자 id 없음 | `subject_id: null` | 만들지 않음 (`baseline_valid=0`) |

함께 넘겨 주셔야 할 것은 다음과 같습니다.
- **라벨 매핑표:** 원 라벨(예: KSS 1–9)을 `0` 정상 / `1` 졸음으로 바꾸는 규칙. 기준이 바뀔 수 있으니 원 라벨도 함께 보관해 주세요.
- **이용 조건:** 재배포 가능 여부. 원본 데이터는 Git에 올리지 않습니다.

## 7. 전달 전 체크리스트

- [ ] 채널별 실제 샘플링 주기 확인 (`fs`)
- [ ] ECG·PPG 시작 시각 정렬
- [ ] NaN·샘플 누락 처리 (4장)
- [ ] 참가자 id 일관성 (같은 사람 = 같은 id)
- [ ] 첫 세션 앞 30초 안정 상태 기준 측정, 품질 기준 확인 (3장)
- [ ] `prefiltered` 표시와 적용한 처리 내역 (`notes`)
- [ ] 라벨 파일과 `label_fs`, 원 라벨 매핑표
- [ ] 원본 생체데이터는 Git이 아닌 별도 경로로 공유

## 8. 미확정 항목 (확정되면 이 문서 갱신)

- 졸음 정답 기준 (교사 모델 의사 라벨 / 자가 보고 / KSS 경계값)
- 윈도우 길이 (현재 30초 / 10초 이동, 임시)
- 기업 제공 PPG 보정 로직 적용 위치
- 샘플 누락 판단 기준이 될 타임스탬프 전송 방식 (Arduino → Pi)

## 9. v0.3 추가 사항 (선택 필드, 2026-11-05)

모두 선택이며 없으면 v0.2 와 똑같이 동작합니다. 로더는 모르는 필드를 `Recording.meta` 로 넘깁니다.

| 필드 / 파일 | 의미 |
| --- | --- |
| `channels` | 실제 있는 채널 목록. 없으면 `["ecg", "ppg"]`. 교사 학습 데이터처럼 ECG 만 있으면 `["ecg"]` |
| `drowsiness_inducer` | `sleep_deprivation` / `prolonged_driving` / `mental_fatigue` / `none`. 평가 보고용, 모델 입력 아님 |
| `baseline_range` | 기준 구간 [시작 s, 끝 s]. 세션 앞부분이 아닌 기준 구간 (예: 연습 주행 뒤 5분) |
| `baseline_per_session` | `true` 면 세션마다 자기 기준 구간 (녹화 날짜가 다를 때) |
| `mains_hz` | 전원 주파수 50/60. 있으면 노치 필터를 그 값으로 |
| `labels_orig.csv` | 원 라벨 + 측정 시각 (KSS 값, 피로 단계, 이벤트 시각). 이진 기준을 바꿔도 재변환 불필요 |
| `labels_window.csv` | 교사가 만든 창 단위 라벨 (`t_start, label`). 학생 창과 `t_start` 로 1:1 |

`write_session()`(`driver_state.data_io`)으로 이 구조를 쓸 수 있습니다. 신호는 `data.npz`(float32)로 저장합니다.
