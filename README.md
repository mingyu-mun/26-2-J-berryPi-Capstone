# J_Berry PI · 2026-2 Capstone

**On-Device AI 기반 차량 운전자 상태 분석 및 개인화 서비스**

ECG·PPG 생체신호를 중심으로 차량 CAN 데이터를 보조 정보로 활용하여, 운전 중 운전자의 특이사항과 상태 변화를 Raspberry Pi 내부에서 판단하는 캡스톤디자인 프로젝트입니다. 카메라 없이 생체센서 기반으로 개발합니다.

> 현재 단계: 공개 데이터 기반 모델 골조와 센서 수집 환경 준비. 구매 목록은 정리 완료했으며, 데이터셋과 모델 구조는 검토 중입니다. 이 저장소에는 실행 가능한 모델이나 서비스가 아직 등록되지 않았습니다.

## 현재 개발 방향

2026.10.05 회의와 2026.10.07 구매 목록 정리 내용을 반영했습니다.

- **공개 데이터 우선:** 센서 수령 전 공개 데이터셋으로 모델의 학습·평가 골조를 구성하고, 이후 직접 수집한 센서 데이터와 비교 검증합니다.
- **데이터 확보 우선:** 데이터셋 구성을 먼저 진행합니다. 데이터 담당 2명·AI 담당 1명 배치 방안이 논의됐으며, 세부 인력 배치는 팀에서 조율합니다.
- **투 트랙 비교:** 서로 다른 접근을 병행해 비교한 뒤 최종 방식을 선택합니다. 구체적인 비교 모델은 아직 확정하지 않았습니다.
- **작은 CNN 검토:** 모델 크기를 작게 유지하는 방향으로 CNN 초안을 개발합니다. 최종 구조는 데이터셋과 라벨을 확인한 뒤 선정합니다.
- **단순한 UI부터:** 초기 화면은 상태 표시 중심으로 구성하고, 필요에 따라 개선합니다.
- **2주 단위 진행:** 데이터 확보, 모델 개발, 센서 검증을 마일스톤별로 관리합니다.

## 개발 목표

1. **데이터 전처리:** ECG·PPG와 CAN의 시간축 동기화, 노이즈·모션 아티팩트 저감, 특징 추출.
2. **운전자 상태 판단:** 생체 특징을 중심으로 차량 특징을 보조 정보로 사용하는 AI 모델 개발.
3. **개인화:** 운전자별 생체정보·운전습관 프로필을 로컬에 저장하고 평상시 대비 변화량을 판단에 반영.
4. **On-Device 추론:** Raspberry Pi 기반 프로토타입에서 오프라인 연속 추론 구현.
5. **서비스 연계:** HMI 상태 표시와 알림을 검토하고, 필요 시 휴식 권고·부저·LED 및 개인화 서비스로 확장.
6. **Replay:** 실시간 데이터 확보가 어려운 경우 동일 프로그램에서 파일 재생 입력 지원.

### 분류 및 데이터 관련 현재 합의 수준

- 착수발표의 초기 목표는 **매우 양호 / 양호 / 피로 / 상태 이상**의 4단계 분류입니다.
- 후속 질의 정리에서는 상태 명칭이 임시 용어이며, 라벨은 정수값보다 구간화하는 방향이 선호된다고 기록되어 있습니다. 최종 클래스 수, 경계와 정답 기준은 미확정입니다.
- 생체데이터 : 차량데이터 **8:2** 비율이 권장되었습니다. 입력 개수, 특징 비중 또는 모델 가중치를 뜻하는지는 추가 확인이 필요합니다.
- 개인화 Baseline은 가능하다면 구현하는 방향이며, HMI도 결과물 품질 향상을 위한 권장 사항입니다.

### 데이터 확보 및 모델링

- 기업 전달자료는 센서 입력·신호처리 참고자료와 CAN 로그입니다. ECG·PPG·CAN 및 운전자 상태 정답이 결합된 완성 학습 데이터셋은 제공자료에 포함되어 있지 않아, 데이터 구성과 라벨 기준 설계가 필요합니다.
- 제공 CAN 로그는 BLF·ASC 형식으로 읽을 수 있습니다. 신호 정의와 상황별 맥락이 부족하므로, 속도·RPM 등 물리 신호의 해석과 생체 데이터 대응 관계를 확인해야 합니다.
- ML 모델링은 전처리가 끝난 입력을 받아 모델 구조, 학습, 평가와 개인화 결합을 담당합니다. 입력 형태·구간·라벨은 데이터/전처리 담당과 합의합니다.
- 양자화는 초기 필수 작업으로 두지 않고 작은 모델로 시작합니다. 적용 필요 여부는 실제 보드의 추론시간과 메모리 측정 후 판단합니다.

착수발표와 초기 질의의 상세 내용은 [자료 및 질의 정리](docs/context-notes.md), 초기 설계 쟁점은 [데이터·모델 설계 메모](docs/data-and-model.md)에 정리되어 있습니다. 현재 진행 방향은 위 회의 반영 내용을 기준으로 합니다.

## 하드웨어 계획

정리된 `J_Berry_PI_부품구매리스트.xlsx` 기준입니다. 아래는 구매 계획이며 주문·수령 완료를 의미하지 않습니다.

| 구분 | 구성 | 용도 |
| --- | --- | --- |
| 기본 구성 | Raspberry Pi 4B 4GB | 전처리, AI 추론, 상태 표시 |
| 기본 구성 | Arduino Nano, AD8232 ECG 센서, XD-58C 아날로그 PPG 센서 | 생체신호 수집 및 Pi 전달 |
| 기본 구성 | 전원, 케이스·쿨러, microSD, RTC | 실행 환경, 저장 및 시간 관리 |
| 기본 구성 | 버튼, LED, 부저 | 사용자 선택, 측정 시작, 상태 알림 |
| 선택 | 보조배터리, 7인치 디스플레이, MAX30102 디지털 PPG 센서 | 이동 측정, 화면 출력 및 PPG 비교 |
| 보류 | USB-CAN 어댑터, MCP2515 CAN 모듈 | CAN 연결 방식 협의 후 결정 |

필수 PPG 수집 계획은 XD-58C 아날로그 센서이며, 기업 자료의 MAX30102는 선택 비교 후보로 구분합니다. 세부 수량·상품·금액·배선은 팀에서 관리하는 구매 목록을 참고합니다.

## 처리 흐름

```text
ECG / PPG + 차량 CAN (실시간 또는 파일 Replay)
    → 전처리 및 시간축 동기화
    → 생체 특징 + 보조 차량 특징 추출
    → 운전자 상태 AI 추론 ← 개인별 Baseline / 로컬 프로필
    → 상태 표시 및 알림 / 개인화 서비스 연계
```

첫 단계에서는 공개 데이터로 생체 입력의 모델 골조를 검증하고, 실제 센서 데이터·개인화·CAN 입력은 확보 상태에 따라 단계적으로 결합합니다. 세부 모델 구조와 개인화 결합 방식은 아직 선정하지 않았습니다.
