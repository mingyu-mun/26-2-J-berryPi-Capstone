# J_Berry PI · 2026-2 Capstone

**On-Device AI 기반 차량 운전자 상태 분석 및 개인화 서비스**

ECG·PPG 생체신호를 중심으로 차량 CAN 데이터를 함께 활용하여, 운전 중 운전자의 특이사항과 상태 변화를 차량 내부에서 판단하는 캡스톤디자인 프로젝트입니다.

> 현재 단계: 기획 및 설계 문서 정리. 이 저장소에는 실행 가능한 모델이나 서비스가 아직 없습니다. 아래 기능은 개발 목표이며, 구현 완료를 의미하지 않습니다.

클라우드 연결이 불안정한 환경에서도 판단을 이어가고, 생체정보의 외부 전송을 최소화하는 차량 내부 처리 구조를 목표로 합니다. 개인별 생체신호와 운전습관 차이를 반영하는 Baseline도 검토합니다.

## 개발 목표

1. **데이터 전처리:** ECG·PPG와 CAN의 시간축 동기화, 노이즈·모션 아티팩트 저감, 특징 추출.
2. **운전자 상태 판단:** 생체 특징을 중심으로 차량 특징을 보조 정보로 사용하는 AI 모델 개발.
3. **개인화:** 운전자별 생체정보·운전습관 프로필을 로컬에 저장하고 평상시 대비 변화량을 판단에 반영.
4. **On-Device 추론:** Linux 기반 SBC 또는 동급 플랫폼에서 오프라인 연속 추론 구현.
5. **서비스 연계:** HMI 상태 표시와 알림을 검토하고, 필요 시 휴식 권고·부저·LED 및 개인화 서비스로 확장.
6. **Replay:** 실시간 데이터 확보가 어려운 경우 동일 프로그램에서 파일 재생 입력 지원.

### 분류 및 데이터 관련 현재 합의 수준

- 착수발표의 초기 목표는 **매우 양호 / 양호 / 피로 / 상태 이상**의 4단계 분류입니다.
- 후속 질의 정리에서는 상태 명칭이 임시 용어이며, 라벨은 정수값보다 구간화하는 방향이 선호된다고 기록되어 있습니다. 최종 클래스 수, 경계와 정답 기준은 미확정입니다.
- 생체데이터 : 차량데이터 **8:2** 비율이 권장되었습니다. 입력 개수, 특징 비중 또는 모델 가중치를 뜻하는지는 추가 확인이 필요합니다.
- 개인화 Baseline은 가능하다면 구현하는 방향이며, HMI도 결과물 품질 향상을 위한 권장 사항입니다.

자세한 근거와 미확정 사항은 [자료 및 질의 정리](docs/context-notes.md), 데이터 설계는 [데이터·모델 설계 메모](docs/data-and-model.md)를 참고하세요.

## 처리 흐름

```text
ECG / PPG + 차량 CAN (실시간 또는 파일 Replay)
    → 전처리 및 시간축 동기화
    → 생체 특징 + 보조 차량 특징 추출
    → 운전자 상태 AI 추론 ← 개인별 Baseline / 로컬 프로필
    → 상태 표시 및 알림 / 개인화 서비스 연계
```

세부 모델 구조와 개인화 결합 방식은 아직 선정하지 않았습니다.
